## 실행 확인 (실측, macOS · Node v24.22.0)

| 명령 | 결과 |
|---|---|
| `npm run check` | 문법 오류 없음 |
| `npm start` | "케셰브 연결 확인: http://127.0.0.1:5189" 출력, 화면 열림, `/api/me`는 `ENGINE_NOT_CONNECTED`, 화면 배지는 "연결 없음" |
| `npm run demo` | "케셰브 예제: http://127.0.0.1:5189" 출력, `/api/me`·`/api/events`·`/api/vulnerabilities` 응답 200, 화면 배지는 "예제 데이터(demo) · 실제 연결 아님" |

`npm start`에서 "연결 없음"이 나오는 것은 이 Mac에 연결할 기존 서버·에이전트가 없기 때문이며, 오류가 아니라 의도한 안내입니다.

## 기능 점검표

| 기능 | 연결 없음 (`npm start`, 실측) | 데모 (`npm run demo`, 예시 값) | 실제 연결 | 지금 상태 |
|---|---|---|---|---|
| 기록 보기 (보안 기록 목록·상세) | 기록 없이 연결 없음 안내 | 예시 기록 1건(`event-01`)이 API로 나옴. 화면 확인은 이전 단계 기록을 따름 | 미확인 | 데모에서 됨 |
| 내 PC 상태 (로그인·기기·세션) | 사용자·기기·세션이 "확인 불가 (요청 실패)", 학생 표시는 연결 없음 문구 (화면 확인) | 연습 사용자 · 연습 PC · 활성 세션이 값마다 `demo` 표시와 함께 나옴 (화면 확인). 기기 상태 "확인 불가(unknown)"도 예시가 준 값 | 미확인 | 데모에서 됨 |
| 위험 알림 | 연결 실패 사유만 목록에 나옴 | 상태 화면에 알림 목록은 있음. 데모 데이터에는 알림 조건이 약해 비어 있을 수 있음 | 미확인 | 일부 됨 (목록만, 우선순위·강조 없음) |
| AI 연결·설명 | 안 됨 | 모의 상태만 | 미확인 | 안 됨 (실제 성공 못 봄) |
| 취약점·설치 패키지 표 | 안 됨 | `not_configured`라 표가 비어 있음 | 미확인 | 표 확인 못 함 |
| 조치 집행 | 안 됨 | 조치 버튼은 `미지원`으로 비활성 | 미확인 | 안 됨 (의도적으로 미지원) |

## 다듬을 핵심 기능 3가지

| 순서 | 기능 | 고른 이유 | 이번에 다듬을 방향 |
|---|---|---|---|
| 1 | 기록 보기 | 매일 열어 볼 이유가 가장 크고, 목록·상세·필터가 이미 있음 | 오래된·새 기록을 한눈에 구분하고 찾기 쉽게 정리 |
| 2 | 내 PC 상태 | 신원·기기·세션 표시와 도움정보가 이미 있어 바로 다듬을 수 있음 | 연결 여부와 확인 불가 이유를 한 곳에 모아 보이기 |
| 3 | 위험 알림 | 앱의 존재 이유. 알림 목록은 있으나 위험도 구분이 없어 가장 손이 많이 감 | 위험한 알림을 먼저 보이고, 실제와 예시를 구분해 표시 |

**순서 이유:** 앞의 두 기능은 이미 되므로 먼저 다듬고, 새로 만들 부분이 가장 많은 위험 알림은 마지막에 합니다.

**이번 기간에 하지 않는 것:** 조치 집행, 실제 AI 연결 성공 확인, 취약점 표 실데이터 확인 (이 Mac에서 확인할 수 없거나 위험이 큼).

## 같은 결과를 다시 만드는 순서

1. `cd <저장소 폴더>/on-client`
2. `npm run check`
3. `npm run demo` 실행 후 브라우저에서 `http://127.0.0.1:5189` 열기 (끌 때는 터미널에서 Ctrl+C)
4. `npm start`도 실행해 "연결 없음" 안내가 나오는지 확인 (먼저 3번을 끄고 실행)

## 미확인·남은 것

- 실제 연결 모드의 기록·PC 상태는 이 환경에서 본 적이 없습니다.
- 데모의 보안 기록 상세 화면과 위험 알림 목록은 1일차에 화면으로 다시 보지 않았습니다.
- `/api/status` 주소는 404였습니다. 제가 추측한 주소라 앱 오류인지 알 수 없습니다.

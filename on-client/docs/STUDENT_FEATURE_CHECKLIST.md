## 다듬을 핵심 기능 3가지

| 순서 | 기능 | 고른 이유 | 이번에 다듬을 방향 |
|---|---|---|---|
| 1 | 기록 보기 | 매일 열어 볼 이유가 가장 크고, 목록·상세·필터가 이미 있음 | 오래된·새 기록을 한눈에 구분하고 찾기 쉽게 정리 |
| 2 | 내 PC 상태 | 신원·기기·세션 표시와 도움정보가 이미 있어 바로 다듬을 수 있음 | 연결 여부와 확인 불가 이유를 한 곳에 모아 보이기 |
| 3 | 위험 알림 | 앱의 존재 이유. 알림 목록은 있으나 위험도 구분이 없어 가장 손이 많이 감 | 위험한 알림을 먼저 보이고, 실제와 예시를 구분해 표시 |

**순서 이유:** 앞의 두 기능은 이미 되므로 먼저 다듬고, 새로 만들 부분이 가장 많은 위험 알림은 마지막에 합니다.

**이번 기간에 하지 않는 것:** 조치 집행, 실제 AI 연결 성공 확인, 취약점 표 실데이터 확인 (이 Mac에서 확인할 수 없거나 위험이 큼).

# 2일차: 내 PC의 CPU·메모리·디스크 실측 (2026-11-03)

## 제공 부분과 학생이 바꾼 부분

제공된 「내 PC 상태」는 CPU·메모리·디스크를 재지 않습니다. 제공 쪽에는 기기·세션 상태(`/api/devices`, `/api/sessions`)만 있고(코드에서 `cpu`·`memory`·`disk`·`statfs` 를 검색해 확인), 그래서 측정 기능은 새로 만들었습니다.

| 파일 | 구분 | 바꾼 내용 |
|---|---|---|
| `student/pc-status.mjs` (새 파일) | 학생 | CPU(0.25초 구간 평균)·메모리·디스크 남은 공간을 Node 기본 기능(`os`, `fs.statfs`)으로 한 번 잼. 값마다 단위·잰 시각. 못 읽으면 `unavailable` 과 이유 코드(`NOT_SUPPORTED`·`PERMISSION_DENIED`·`NOT_FOUND`·`READ_FAILED`). 경로·원문 오류는 내보내지 않음 |
| `student/extension.mjs` | 학생 | `renderStatus` 맨 위에 「내 PC 상태」 추가. 최신 값 표, 직전 대비, 최근 5번 표, 「PC 상태 다시 재기」 버튼. `createStudentView` 가 제공 통로(`api.get`)와 다시 그리기(`onChange`)를 받아 씀 |
| `src/server.mjs` | **제공 파일에 학생이 추가** | import 1줄과 `GET /api/pc-status` 경로 1개(2줄) |
| `public/app.js` | **제공 파일에 학생이 추가** | `STUDENT_GET_PATHS` 배열에 `'/api/pc-status'` 한 줄 |
| `docs/STUDENT_RUNBOOK.md` | 문서 | 새 기능과 어긋나는 문장(학생 파일 한 개, 서버 요청 없음 등)을 고침 |

## 값을 읽는 방법 (관리자 권한 없음)

| 값 | 읽는 곳 | 계산 |
|---|---|---|
| CPU 사용률 | `os.cpus()` 를 0.25초 간격으로 두 번 읽음 | 두 번 사이 `idle` 증가분으로 구간 평균 사용률 계산 |
| 메모리 | `os.totalmem()` · `os.freemem()` | 사용량 = 전체 − 운영체제가 알려 준 남은 메모리 |
| 디스크 | `fs.statfs(서버를 실행한 폴더)` | 남은 공간 = 일반 사용자가 쓸 수 있는 블록(`bavail`) × 블록 크기 |

화면의 GB 는 1GB = 1,024³바이트 기준입니다(작업 관리자와 같은 방식).

## 실측 결과 (2026-11-03, 이 Mac, 운영체제 도구와 대조)

| 항목 | 앱 값 | 운영체제 도구 값 | 판단 |
|---|---|---|---|
| 디스크 전체 | 460.4 GB | `df` 482,746,452KB = 460.4GiB | 같음 |
| 디스크 남은 공간 | 239.8 GB | `df` 251,404,144KB = 239.8GiB | 같음 |
| 메모리 전체 | 16.0 GB | `sysctl hw.memsize` 17,179,869,184바이트 | 같음 |
| 메모리 사용 | 15.7~15.8 GB (98%) | `vm_stat` free 페이지 15,236개 × 16KB ≈ 0.25GB | 남은 공간이 거의 없다는 점이 같음 |
| CPU 사용률 | 10.9~16.3 % (0.25초 구간) | `top` 11.7~11.2 % (구간이 달라 조금 다름) | 같은 범위 |

**메모리가 98%로 높게 나오는 이유:** macOS 는 캐시로 쓰는 메모리를 "남은 메모리"에서 빼서 알려 줍니다. 활동 상태 보기의 "메모리 사용"과 다르며, 화면에 이 안내(macOS 한정)를 적었습니다.

## 화면에서 확인한 것 (실제 Chrome)

- 예제(`npm run demo`)와 연결 없음(`npm start`) 두 모드 모두 같은 실측값이 나옵니다. 측정은 기존 서버·에이전트 연결과 무관하기 때문입니다. 단, 같은 화면의 기기·세션 값은 모드에 따라 예제 또는 확인 불가입니다.
- 「PC 상태 다시 재기」를 누르면 직전 대비(예: CPU +4.2%p, 디스크 변화 없음)와 최근 측정 표가 생깁니다.
- 읽기 실패는 실제로 만들어 확인했습니다: 없는 경로 → 디스크 `NOT_FOUND`, 권한 없는 폴더 → `PERMISSION_DENIED`. CPU·메모리는 정상 값이 유지되고 디스크 값은 숫자 없이 확인 불가와 이유만 나옵니다.

## 코드 점검

- `node --check` 4개 파일 통과 (`student/pc-status.mjs`, `student/extension.mjs`, `src/server.mjs`, `public/app.js`).

- 이전 단계 화면(13~20)을 위한 점검 스크립트는 사라져 이번에 다시 돌리지 못했습니다. 브라우저에서 보호 현황 화면의 기기·세션·알림이 계속 표시되는 것만 확인했고, 다른 탭(업무 앱·보안 기록)과 AI·조치·취약점 화면은 이번에 다시 보지 않았습니다.

## 미확인·주의

- **Windows 에서는 확인하지 못했습니다.** 같은 Node 기능을 쓰지만 이 Mac 에서만 실측했습니다.
- 작업 관리자·활동 상태 보기 화면과 직접 비교하지 않고, 같은 정보를 주는 명령줄 도구(`df`·`top`·`sysctl`·`vm_stat`)와 비교했습니다.
- CPU 는 0.25초 구간 평균이라 한 번 재면 값이 크게 흔들릴 수 있습니다(같은 상태에서 10.9~16.3%).
- 추이는 화면을 연 동안만 메모리에 있습니다. 새로고침하면 사라지고 파일로 저장하지 않습니다.
- 제공 파일(`src/server.mjs`, `public/app.js`)을 고쳤으므로, 시작 틀을 0.2.21 로 업데이트하면 이 두 곳이 덮어써질 수 있습니다. 업데이트 전에 이 문서의 표대로 다시 적용해야 합니다.

# 3일차: 연결 상태·방화벽 설정·Windows 기록 건수를 읽기만 해서 보여 주기 (2026-11-03)

## 한눈에 보기

| 항목 | 이 Mac (실측) | Windows PC |
|---|---|---|
| 네트워크 연결 | 읽음: `en0` 무선, IPv4 설정 있음 | **미확인** (코드는 있음) |
| 방화벽 설정 | 읽음: macOS 방화벽 켜짐 | **미확인** (코드는 있음) |
| Windows System·Application 기록 건수 | **확인 불가 · Windows 전용** (이 PC 는 macOS) | **미확인** (코드는 있음) |
| SDP 서버 연결 상태 | PC 조회와 따로 표시: 연결 없음 모드 `SDP 미연결(disconnected)`, 예제 모드 `예제(demo)` | 같음 |

**Windows 쪽 코드는 이 Mac 에서 실제로 실행해 본 적이 없습니다.** 가짜 PowerShell 출력(모의 값)으로 해석 부분만 점검했습니다. Windows PC 에서 실제로 읽히는지는 아래 "Windows 에서 직접 확인" 순서로 확인해야 합니다.

## 화면에 반드시 적은 것

- 경고·오류 건수는 운영체제가 남긴 기록의 개수일 뿐이며, 침해나 공격을 탐지한 결과가 아닙니다. (표 위 안내문과 기록 행 설명에 모두 적음)
- 방화벽·보안 설정은 읽기만 하고 바꾸지 않습니다. 관리자 권한이 필요한 항목은 읽지 않고, 못 읽으면 확인 불가와 이유를 보여 줍니다.
- SDP 연결 상태는 표 밖에 따로 적고 "PC 조회 결과와 별개"라고 밝혔습니다. PC 조회가 실패해도 SDP 줄은 그대로이고, SDP 가 미연결이어도 PC 값은 실측값으로 남습니다.
- 네트워크 "연결됨"은 이 PC 의 인터페이스에 IPv4 설정이 있다는 뜻일 뿐, 인터넷에 실제로 닿는지는 확인하지 않았습니다. IP·MAC 주소는 화면과 응답에 넣지 않았습니다(인터페이스 이름·종류만).
- 실측값과 예제 자료를 구분하는 문구: 이 블록은 "실측값… 예제(demo) 자료와 다릅니다", SDP 줄은 모드에 따라 "예제(demo) 자료입니다" 또는 "SDP 미연결".

| `docs/STUDENT_RUNBOOK.md` | 문서 | 새 기능과 어긋나는 문장(학생 파일 수, 서버 요청 예외 등)을 고침 |

## 실행하는 명령 (모두 읽기 전용, 이 목록 밖의 명령은 실행하지 않음)

| 운영체제 | 읽는 것 | 명령 |
|---|---|---|
| 모든 OS | 연결된 인터페이스 | Node `os.networkInterfaces()` (명령 실행 없음) |
| macOS | 인터페이스 종류 | `networksetup -listallhardwareports` |
| macOS | 방화벽 | `socketfilterfw --getglobalstate` |
| Windows | 인터페이스 종류 | `Get-NetAdapter \| Where-Object Status -eq 'Up' \| Select-Object Name,PhysicalMediaType` |
| Windows | 방화벽 | `Get-NetFirewallProfile \| Select-Object Name,Enabled` |
| Windows | System·Application 기록 | `Get-WinEvent -FilterHashtable @{LogName=…; Level=2 또는 3; StartTime=24시간 전}` 의 **개수만** |

- Security 기록은 관리자 권한이 필요해서 읽지 않습니다.
- 점검에서 모든 실행 명령에 `Set-`·`New-`·`Remove-`·`Enable-`·`Disable-`·`netsh` 같은 쓰기·설정 단어가 없고 `Get-` 계열만 있는지 확인합니다.
- 읽는 기간은 최근 24시간입니다.

## 이 Mac 에서 실제로 확인한 것

- 서버 응답과 Chrome 화면(예제 모드·연결 없음 모드 모두)에서 네트워크 `en0(무선)`, 방화벽 `macOS 방화벽 켜짐`, Windows 기록 두 줄 `확인 불가`(이유: Windows 에서만 읽음, 서버가 실행 중인 PC(macOS))를 봤습니다.
- 「연결·기록 다시 읽기」를 누르면 읽는 동안 버튼이 비활성화되고 읽은 시각이 바뀝니다. 같은 화면의 2일차 「내 PC 상태」는 그대로 있습니다.
- 방화벽 값은 운영체제 명령(`socketfilterfw --getglobalstate` → "Firewall is enabled")과 같습니다.

## 코드 점검 (임시 스크립트라 저장소에는 넣지 않음)

- 읽기 모듈 40개: Windows 모의 출력 해석(유선·무선 구분, 방화벽 숫자 값 1/0/2, 기록 건수 0 건), 항목별 실패가 서로 퍼지지 않음, 이상한 출력 거부, 예외 시 확인 불가, macOS 에서 PowerShell 안 부름, 읽기 전용 명령만 쓰는지, IP·MAC 미노출, 실행기의 권한 없음·시간 초과 분류(실제 프로세스로 확인).
- 화면 43개: 정상 값, macOS 확인 불가, 이상한 값 거부, 요청 실패 시 오류 코드만, 한 번만 요청, 버튼 비활성, SDP 4가지 상태와 분리, 늦은 응답 버림.
- 2일차 점검 41개도 다시 통과(회귀 없음).
- 변이 점검(코드를 일부러 망가뜨림): 읽기 모듈 16가지·화면 13가지를 시도했습니다. 처음에 놓친 2가지(화면의 인터페이스 종류 검증 제거, 읽기 모듈의 권한 오류 분류)는 점검을 보강해 잡았고, 시간 초과 분류와 쓰기 명령·`netsh` 사용 변이는 보강한 점검으로 처음부터 잡았습니다. 예외 처리를 지운 변이는 점검이 비정상 종료(처리되지 않은 오류)로 드러냈습니다.

## 같은 결과를 다시 만드는 순서 (Mac)

1. `cd <저장소 폴더>/on-client`
2. `node --check student/pc-security.mjs && npm run check`
3. 켜져 있는 케셰브 서버가 있으면 `Ctrl+C` 로 끕니다(포트 5189 가 같음).
4. `npm run demo` 실행 후 `http://127.0.0.1:5189` → 「보호 현황」에서 「연결과 기록」 확인. SDP 줄이 "예제(demo)"로 나오고 표에는 SDP 가 섞이지 않았는지 봅니다.
5. `Ctrl+C` 후 `npm start` 로 다시 열어 SDP 줄이 "SDP 미연결(disconnected)"로 바뀌고 PC 값은 그대로 나오는지 봅니다.
6. 「연결·기록 다시 읽기」를 눌러 읽은 시각이 바뀌는지 봅니다.

## Windows 에서 직접 확인 (미확인 항목을 확인하는 순서)

1. Windows PC 에서 저장소를 받고 `on-client` 에서 `npm run demo` 를 실행합니다(관리자 권한으로 실행하지 않습니다).
2. 「연결과 기록」에서 네트워크가 `Wi-Fi(무선)` 또는 `Ethernet(유선)` 으로 나오는지 봅니다.
3. 방화벽에 Domain·Private·Public 이 켜짐/꺼짐으로 나오는지 봅니다. `확인 불가 · 일반 권한으로는 읽을 수 없었습니다` 가 나오면 그대로 두고, 설정을 바꾸지 않습니다.
4. System·Application 에 `오류 N건 · 경고 M건 (최근 24시간)` 이 나오는지 봅니다. Windows 이벤트 뷰어에서 같은 로그를 24시간 필터(수준: 오류·경고)로 열어 건수를 비교합니다. 몇 초 사이에 새 기록이 생길 수 있어 조금 다를 수 있습니다.
5. 값이 안 나오면 새 폴더를 만들지 말고 화면의 확인 불가 이유를 그대로 복사해 AI 에게 보여 주세요.

## 미확인·주의

- **Windows 에서 실제 실행은 미확인**입니다. PowerShell 명령과 출력 모양은 문서·관례로 작성했고, 가짜 출력으로만 해석을 점검했습니다. 특히 `Get-NetFirewallProfile` 이 일반 권한에서 항상 읽히는지는 모릅니다.
- 이 Mac 에서는 Windows 기록이 확인 불가로만 나옵니다. 건수 화면은 모의 값으로만 봤습니다.
- 한 번 읽는 데 Windows 에서는 PowerShell 을 최대 4번 띄웁니다(동시에 실행, 각 8초 제한). 화면을 열 때와 버튼을 누를 때만 읽습니다.
- 경고·오류 건수는 정상적인 PC 에서도 흔하게 쌓입니다. 침해 여부와 무관하며, 이 앱은 건수의 의미를 판단하지 않습니다.
- 제공 파일(`src/server.mjs`, `public/app.js`)을 고쳤으므로 시작 틀을 0.2.21 로 업데이트하면 이 변경이 덮어써질 수 있습니다.

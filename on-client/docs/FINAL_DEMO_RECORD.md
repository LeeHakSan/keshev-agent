## 2. 핵심 기능 3개

### 핵심 기능 1 — 기록 보기
- 제공된 부분: 「보안 기록」 화면의 목록·필터·상세·AI 설명/조치 버튼 틀(시작 틀 0.2.14 의 `public/`, `src/`).
- 내가 직접 한 부분: 13~22단계에서 `student/extension.mjs` 의 `renderEvents` 등 표시 함수를 작성. 완성본에서는 「핵심 3가지」 첫째 칸에 「보안 기록」 안내를 둠(기록 건수는 세지 않음).
- **계획했으나 못 한 것:** 1일차 점검표에서 정한 "오래된·새 기록을 한눈에 구분하고 찾기 쉽게 정리"는 구현하지 않았습니다.
- 실제 확인 결과: 예제 모드에서 목록 1건·필터·상세 화면이 뜨는 것을 헤드리스 Chrome 으로 읽어 확인했습니다. **실제 기록은 한 번도 보지 못했습니다.**
- 연결 실패 때의 동작: 연결 없음(`npm start`)에서는 기록 없이 연결 없음 안내가 나옴(1일차 Mac 실측). 여러 건·빈 목록의 실제 화면은 미확인.
- 근거: `on-client/docs/STUDENT_FEATURE_CHECKLIST.md`, `on-client/docs/STUDENT_RELEASE_RECORD.md` 4장.

### 핵심 기능 2 — 내 PC 상태
- 제공된 부분: 기기·세션 상태 표시 틀(`/api/devices`, `/api/sessions`). 제공 쪽에는 CPU·메모리·디스크를 재는 기능이 **없습니다**(2일차에 코드 검색으로 확인).
- 내가 직접 한 부분(새로 만듦):
  - `student/pc-status.mjs`: CPU(0.25초 구간 평균)·메모리·디스크를 Node 기본 기능으로 읽음. 못 읽으면 `unavailable` 과 이유 코드.
  - `student/pc-security.mjs`: 네트워크 인터페이스(이름·종류만), 방화벽 켜짐 여부, Windows System/Application 기록의 최근 24시간 오류·경고 **건수만**. 고정된 읽기 전용 명령만 실행, 셸 없음, 8초 제한, IP·MAC 미노출.
  - `student/extension.mjs`: 「핵심 3가지 한눈에 보기」, 다시 조회 버튼, 직전 대비, 최근 5번 표, 실패 화면, 키보드 포커스 유지.
- 실제 확인 결과: **됨 (실측).** Mac 과 Windows 11 두 곳에서 운영체제 값과 대조했습니다.
  - 디스크 남은 공간·전체, 메모리 전체는 운영체제 값과 같음, 메모리 사용·CPU 는 같은 범위(측정 시각·구간 차이).
  - Windows 방화벽·System/Application 기록 건수는 PowerShell 로 직접 센 값과 같음.
- 연결 실패·잘못된 입력 때의 동작: 없는 경로 → 디스크 `NOT_FOUND`, 권한 없는 폴더 → `PERMISSION_DENIED`(CPU·메모리는 유지). 서버를 끄면 `NETWORK_ERROR` 실패 화면과 다음에 할 일, 직전 값 표시.
- 근거: `STUDENT_FEATURE_CHECKLIST.md` 의 2·3·4일차와 「Windows 실측 확인 (2026-11-06)」.

### 핵심 기능 3 — 위험 알림
- 제공된 부분: 서버가 알려 준 기기·세션·기록의 주의 항목을 모으는 목록(`renderStatus` 의 알림 목록).
- 내가 직접 한 부분: 「핵심 3가지」 셋째 칸에 「주의 N건」 요약, 출처(기기·접속 기록) 표시, 「침해나 공격 판정이 아닙니다」 문구, 예제(demo) 자료 표시.
- **계획했으나 못 한 것:** "위험한 알림을 먼저 보이게(우선순위·강조)"는 구현하지 않았습니다. 알림은 서버가 준 순서대로입니다.
- 실제 확인 결과: 예제 모드에서 「주의 2건」과 두 항목(기기 `unknown`, 접속 기록 `event-01`)이 뜨는 것을 확인. **알림 값은 예제(demo) 자료이며 실제 위험 탐지 결과가 아닙니다.**
- 연결 실패 때의 동작: 연결 없음에서는 연결 실패 사유만 목록에 나옴(1일차).
- 근거: `STUDENT_FEATURE_CHECKLIST.md` 1·4일차.

## 10. 같은 결과를 다시 만드는 순서

1. 비어 있는 새 폴더에서 `git clone https://github.com/LeeHakSan/keshev-agent.git` → `cd keshev-agent/on-client` (Windows 는 `\`).
2. `npm run check` (출력이 없으면 정상).
3. `npm run demo` 후 `http://127.0.0.1:5189` 를 열고 1절 시연 순서대로 확인합니다.
4. 끌 때는 서버를 켠 터미널에서 `Ctrl+C`.
5. 제출할 값: `git rev-parse HEAD` 의 40자리와 저장소 주소. 두 값을 방어전 화면이 아니라 과제 화면의 「마무리 자료 제출」에 적습니다.
6. GitHub 와 같은지 확인: `git ls-remote origin refs/heads/main` 의 번호가 5번과 같아야 합니다.
